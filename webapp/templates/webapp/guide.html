How the matching works

A Stripe payment is the processing record and a QuickBooks payment the accounting record. finrecon pairs them in three steps and stops when a step would have to guess.

  • 1. Exact reference. The PaymentIntent id the sync writes into the QBO memo.
  • 2. One corroborated candidate. Same client, currency and amount within 3 days, with nothing that contradicts it.
  • 3. A typed exception. Missing, duplicate, mismatched, or a case for a person.

How to use the dashboard

Three steps cover a month-end check. Totals are compared and never added: Stripe collected {{ o.stripe_gross_cents|money }} and QuickBooks recorded {{ o.recorded_payments_cents|money }}.

  • 1. Start at priority 1. The exception queue lists what is wrong in the books first. Click a row to see why.
  • 2. Open the record. Each record shows the reason, both amounts, the IDs on each side and the raw API pages.
  • 3. Check the sources. Data quality says whether every pull was complete before you trust a total.

A failed source pull is never $0

Every source and location gets a status. Zero means the source answered zero; a pull that failed or came back short is shown as missing data and never replaces the last good one.
